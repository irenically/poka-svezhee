# Пока свежее

Мобильное веб-приложение для учёта продуктов в холодильнике и морозилке.
Интерфейс построен на Material UI с отдельной зелёной темой приложения; нативные элементы оставлены для камеры и выбора файла.

## Запуск

```sh
npm ci
npm run dev
```

## Возможности

- Добавление по названию или штрихкоду. При открытии формы камера запускается сразу; код можно также ввести вручную.
- Поиск упакованного товара и его категории в Open Food Facts; неизвестный штрихкод запоминается после ручного ввода.
- Холодильник, морозилка и отдельная аптечка; категории с ручным выбором и фильтром, количество с кнопками −/+ и единицами шт, г, кг, мл, л.
- В аптечке фото упаковки предлагает название и дату; оба поля нужно проверить перед сохранением. Если они на разных сторонах коробки, можно сделать два снимка. Пищевая база штрихкодов и подсказки сроков свежих продуктов к лекарствам не применяются.
- Дата на упаковке или дата проверки свежести. В интерфейсе даты показаны в литовском порядке `ГГГГ-ММ-ДД`.
- Фото упаковки для продуктов и лекарств: Tesseract.js распознаёт текст в браузере, предлагает название и найденную дату или выбор между несколькими вариантами. Поддерживаются `ДД.ММ.ГГГГ`, `ДД/ММ/ГГ` и `ГГГГ-ММ-ДД`; для лекарств также `ММ.ГГГГ` (конец месяца). Результат нужно проверить перед сохранением. Языковые модели OCR скачиваются при первом использовании, само фото на сервер не отправляется.
- Подсказки по названию для свежих овощей на основе [USDA FoodKeeper](https://catalog.data.gov/dataset/fsis-foodkeeper-data), а для спелых помидоров — [Nebraska Extension](https://food.unl.edu/free-resource/food-storage/). Дата проверки предлагается автоматически от сегодняшнего дня и редактируется. Это ориентир качества, а не гарантия безопасности.
- Список разделён на секции: просрочено/пора проверить, скоро истечёт, в порядке и без даты. Внутри секций продукты сортируются по срочности; доступны изменение и отметки «съели»/«выбросили».
- Вход по почте и паролю, синхронизация запасов между устройствами через Supabase. Записи из локального прототипа переносятся в аккаунт при первом входе.
- Общий семейный список: владелец создаёт семью и одноразовую ссылку приглашения на 7 дней; второй человек открывает её, входит в собственный аккаунт и подтверждает присоединение. Личные продукты обоих аккаунтов переходят в общий список. Изменения другого участника появляются при возврате в приложение или в течение 30 секунд.
- Для просмотра и изменения запасов нужен вход. Записи из старого локального режима переносятся в аккаунт при первом входе.

Доступ к общему списку ограничен участниками семьи благодаря Row Level Security. Фоновые уведомления пока не добавлены. Для работы камеры нужен HTTPS или localhost.

## Данные и развёртывание

- Схема базы: `supabase/migrations/20261115150000_initial_inventory.sql`.
- Семейный доступ: `supabase/migrations/20261115170000_family_inventory.sql`.
- Категории: `supabase/migrations/20261115190000_inventory_categories.sql`.
- Соусы и консервация: `supabase/migrations/20261115193000_more_inventory_categories.sql`.
- Аптечка: `supabase/migrations/20261115203000_medicine_cabinet.sql`.
- Публикация на GitHub Pages: `.github/workflows/deploy.yml`.
- Ключ Supabase в клиентском коде является publishable key; доступ к строкам ограничен RLS.
- Значения для овощей сверены с данными FoodKeeper FSIS (CC0) по идентификаторам записей, указанным в `src/produce.ts`. Официальный сервер блокировал автоматическое скачивание, поэтому для сверки использована [публичная копия данных](https://github.com/haggman/A4I2026-challenge-2-food-equity/blob/main/data/foodkeeper.json). Официальный [каталог USDA](https://catalog.data.gov/dataset/fsis-foodkeeper-data) остаётся исходным источником.
